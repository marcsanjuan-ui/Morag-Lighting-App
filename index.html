What the simulation shows about the firmware

    
    
      
  • Speed only changes the tick. Speed sets the delay between frames, map(255 − speed, 0, 255, 2, 100), from 100 ms down to 2 ms. A 300-LED frame takes about 9 ms to send, so above speed ≈ 205 the strip can't go any faster.
    • 
      
  • Static presets ignore speed: 22, 23, 24, 35, 36, 37, 43, 44, 45 and 50 are a single fill color.
    • 
      
  • Breathing Red and Heartbeat are slow. They follow hue, which moves 1 step per tick, so a full breath takes 256 ticks: about 13 s at the default speed.
    • 
      
  • Color Wipe (7) never clears. It paints over whatever was on the strip, including the previous preset's colors.
    • 
      
  • Fade effects keep the old frame. Presets that use fadeToBlackBy (4, 6, 8, 19, 20, 29, 30, 38, 39, 42, 49) start on top of the last preset and fade it out.
    • 
      
  • Possible overflow in Beacon Light (30). (sin8(hue) * NUM_LEDS) / 255 reaches 300 when sin8 returns 255. That writes leds[300], one past the end of the array. Use NUM_LEDS - 1 or / 256.
    • 
      
  • Color order. The sketch uses COLOR_ORDER RGB, but its comment says WS2815 is usually GRB. If red and green look swapped on the real strip, change it to GRB. The previews show the intended colors.
